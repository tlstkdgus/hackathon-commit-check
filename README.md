# 마감 후 커밋 검사

제출된 깃허브 레포에 **마감 시각 이후 커밋**이 있는지 확인한다.
멋사대학 14기 중앙해커톤 — 결과물 제출 마감 **8/21(금) 09:59:59**,
즉 **10:00:00부터가 마감 후**다.

의존성 없음. `python check.py`로 바로 돈다.

## 준비

레포 주소를 한 줄에 하나씩 적은 파일을 만든다. 빈 줄과 `#` 주석은 무시한다.

```
# 팀명, 프론트, 백엔드, AI  (팀명은 없어도 됨)
멋사팀, https://github.com/team/front, https://github.com/team/back
https://github.com/other/repo
```

주소는 어떤 형태로 적혀 있어도 읽는다 — `.git` 붙은 것, `/tree/main`이
붙은 것, `git@github.com:` 형태, 그냥 `owner/repo`까지.
프론트·백엔드 칸에 같은 레포를 적은 팀(한 레포로 개발한 경우)은
중복을 제거하고 한 번만 검사한다.

**토큰이 필요하다.** `gh auth login`이 되어 있으면 그 토큰을 자동으로 빌려
쓴다. 아니면 `GITHUB_TOKEN`을 설정한다. 토큰 없이 돌리면 시간당 60회로
막혀서 60팀을 못 돈다.

## 쓰는 법

### ① 마감 직후 — 스냅샷을 찍는다 (8/21 10:00)

```bash
python check.py repos.txt --snapshot snapshot-0821.json
```

각 레포의 **모든 브랜치 SHA**를 기록한다. 이 파일을 지우면 안 된다.

### ② 나중에 — 스냅샷과 대조한다

```bash
python check.py --compare snapshot-0821.json
```

심사 기간 중 아무 때나, 여러 번 돌려도 된다.

### 스냅샷을 못 찍었다면

```bash
python check.py repos.txt
```

커밋 시각만 보는 사후 검사. **아래 한계가 그대로 적용된다.**

## 왜 스냅샷이 필요한가

사후 검사만으로는 **`git push --force`를 잡을 수 없다.**
히스토리를 다시 쓰면 마감 후 커밋이 흔적 없이 사라지고, 남은 커밋은
전부 마감 전으로 보인다. 커밋 날짜도 `git commit --date`로 위조된다.

마감 직후에 SHA를 찍어두면 둘 다 드러난다.

| | 사후 검사 | 스냅샷 대조 |
|---|---|---|
| 마감 후 커밋 추가 | 잡힘 | 잡힘 |
| force-push / rebase | **못 잡음** | 잡힘 |
| 커밋 날짜 위조 | 의심만 표시 | 잡힘 |
| 브랜치 삭제 | **못 잡음** | 잡힘 |

## 결과 읽기

| 표시 | 뜻 |
|---|---|
| `[위반]` | 마감 후 커밋이 실제로 확인됨 |
| `[확인]` | 마감 후 푸시 기록은 있는데 커밋이 안 잡힘 / 비공개 레포 |
| `[오류]` | 레포 접근 불가 (삭제·비공개·주소 오타) |
| `[정상]` | 마감 후 변경 없음 |

`[확인]`이 가장 중요하다. 푸시는 마감 후인데 마감 후 커밋이 없다는 건
브랜치를 지웠거나 히스토리를 다시 썼다는 뜻일 수 있다.

**이 도구는 근거만 내놓고 탈락 여부를 판정하지 않는다.**
리베이스·머지처럼 악의 없는 작업으로도 커밋 시각이 밀리고, `[위반]`으로
찍힌 것이 README 오타 수정일 수도 있다. 판단은 운영진이 한다.

## 테스트

```bash
python test_check.py     # 또는 pytest
```

네트워크를 타지 않는 부분(URL 파싱, 판정 로직)만 검사한다.
**경계 테스트가 중요하다** — 09:59:59는 세이프, 10:00:00은 아웃.
한 칸 잘못 잡으면 정시에 낸 팀이 위반으로 찍힌다.

## 알아둘 것

- **비공개 레포는 404로 보인다.** 삭제·오타와 구분되지 않으므로
  `[오류]`로 나온 팀은 사람이 직접 확인해야 한다.
- **PR 머지 커밋도 잡힌다.** 마감 후 열려 있던 PR이 머지되면 위반으로 찍힌다.
- **자동 봇 커밋도 잡힌다.** dependabot 등이 돌고 있으면 그것도 올라온다.
- 검사 대상은 **모든 브랜치**다. 평가 기준은 main/master지만, 다른
  브랜치에 올린 것도 레포 수정이라 함께 보고한다.
